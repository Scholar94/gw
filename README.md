# CAC Good Works Assembly: Website

A fast, accessible, installable church website. Static files only (no build step needed to run it), a free Firebase project for content and sign-in, and one free Cloudflare Worker that protects every public form.

**Everything here is free and needs no credit card.** Limits are listed at the bottom.

## Project layout (deliberately flat)
All site files sit in the repository root so GitHub Pages and any static host can serve it. The only sub-folder is `.github/workflows/` (GitHub requires it). The production build writes to `dist/`, which is git-ignored and exists only in CI.

## Set-up, in this order (about 60 minutes)
Do the steps in order; each one is optional except 1 and 2, and the site keeps working at every stage.

1. **Firebase (free Spark plan).** Create a project, add a Web app, paste its config into `firebase.js`. Enable *Authentication > Email/Password* (staff) and, if you want visitors to sync devotional notes, *Email link (passwordless)*. Add your site's domain under *Authentication > Settings > Authorized domains*. Create Firestore (production mode). Create staff users, then add a document in `admins/{their uid}` with `role` = `super`, `editor` or `pastor`.
2. **Publish the site.** Push to GitHub, then *Settings > Pages > Source: GitHub Actions*. The `Deploy site` workflow builds, tests and publishes `dist/`. Optional repo variable `SITE_URL` sets your public address (a custom domain, for example). 
3. **Cloudflare Worker (spam protection for all public forms).**
   1. Free Cloudflare account. *Turnstile* > add a widget for your site (managed mode): copy the **site key** into `config.js` > `edge.turnstileSiteKey` and keep the **secret**.
   2. Firebase *Project settings > Service accounts*: create a key (give the account only the role *Cloud Datastore User*). 
   3. Edit `wrangler.toml` `ALLOWED_ORIGINS` to your site origin(s). 
   4. GitHub secrets: `CLOUDFLARE_API_TOKEN` (template "Edit Cloudflare Workers"), `CLOUDFLARE_ACCOUNT_ID`, `TURNSTILE_SECRET`, `FIREBASE_SERVICE_ACCOUNT` (the whole JSON), optional `GOOGLE_API_KEY`. Push: the `Deploy edge Worker` workflow deploys it. 
   5. Put the Worker address in `config.js` > `edge.url` (for example `https://cac-edge.your-name.workers.dev`).
   6. **Only now** deploy the strict rules: `firebase deploy --only firestore`. (Before the Worker works, use `firestore.legacy.rules` temporarily: with the strict rules and no Worker, forms cannot save.)
4. **Daily jobs.** GitHub secrets `FIREBASE_SERVICE_ACCOUNT`, optional variable `YOUTUBE_CHANNEL_ID` (starts with `UC`). The daily job publishes scheduled devotionals, writes the calendar and RSS, imports new YouTube uploads as sermons and rebuilds `podcast.xml`.
5. **Podcast.** Submit `https://YOUR-SITE/podcast.xml` to Apple Podcasts Connect and Spotify for Creators. Apple needs square cover art of 1400 to 3000 px (`podcast-cover.jpg` is a 1400 px starter: replace it with real artwork). Audio must be `https` and support range requests (archive.org, or Google Drive through the Worker). Put your name, email and description under `config.js > podcast`.
6. **Push notifications.** `npx web-push generate-vapid-keys`. Public key into `config.js > push.vapidPublicKey`; GitHub secrets `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`. Visitors turn it on from the devotional page. iPhones only support push for the installed app (Add to Home Screen).
7. **Google Drive media library.** Google Cloud console (free, no card): create a project, enable *Google Drive API*, create an *OAuth client ID (Web)* with your site as an authorised JavaScript origin, set the consent screen to *External/Testing* and add your admins as test users. Create a Drive folder and copy its ID. Put both in `config.js > drive`. The admin dashboard then uploads straight to that folder and shares each file as "Anyone with the link". You can also simply paste a Drive share link anywhere a link is asked for. For audio streaming through the Worker, create an API key restricted to the Drive API and add it as `GOOGLE_API_KEY`.
8. **Monitoring (optional).** Cloudflare *Web Analytics* token into `config.js > monitoring.cloudflareToken`; Sentry free-plan DSN into `monitoring.sentryDsn`. Point a free UptimeRobot monitor at `https://YOUR-WORKER/health` and your site address.
9. **Backups.** Add the secret `BACKUP_PASSPHRASE` (12+ characters; store it in a password manager). The nightly `Encrypted nightly backup` workflow keeps a file for 30 days as a workflow artifact. Open one with `BACKUP_PASSPHRASE=... node backup-decrypt.mjs backup-DATE.bin > backup.json`. Backups are never committed.
10. **Online giving (optional, needs a Paystack business account).** Paystack dashboard > Settings > API keys. Put the *secret* key in the GitHub secret `PAYSTACK_SECRET` (use the test key first), optional variable/`wrangler.toml` `GIVE_CURRENCY` (default `NGN`). The give page then shows a form that sends donors to Paystack's own checkout; on return the Worker verifies the payment with Paystack (and that the amount matches) before the site says thank you. Super admins see gifts under *Admin > Giving*. Live payments need Paystack's business verification (no card, no monthly fee, a per-transaction fee). There is no webhook: if a donor closes the tab before returning, use *Re-check pending payments*.
11. **Event RSVPs.** In *Admin > Events* tick *Accept RSVPs*, set a capacity (0 = no limit) and whether to keep a waiting list. Visitors reserve from the events page (needs the Worker), get a QR ticket (`ticket.html`) and can cancel; cancelling promotes the next person on the waiting list that fits. Ushers open *Admin > RSVPs & check-in* on a phone and scan tickets with the camera (or type the code). Reservations never email anyone automatically (no mail service is included): waiting-list people must reopen their ticket to see if a place opened.
12. **Previews.** For a preview link on every pull request, create a Cloudflare Pages project (Direct Upload) and set repo variable `CF_PAGES_PROJECT` plus the Cloudflare secrets; the `Preview / Cloudflare Pages` workflow does the rest.
13. **Visual tests.** After the first deploy run *Actions > Visual baselines > Run workflow* once (and after any intentional redesign) so screenshots are created on the same OS the tests compare on.

## How the pieces behave
- **Forms** (prayer, newsletter, visit/contact, testimony) go browser → Worker (Turnstile + rate limit + validation) → Firestore. With `edge.url` empty they fall back to writing Firestore directly (needs the legacy rules).
- **Sermons**: YouTube uploads appear automatically; delete one in the admin and it will not come back. Audio sermons can carry chapters (`00:00 Title` per line) and a transcript (`[mm:ss] text`), which visitors can search.
- **Bible**: any reference in a devotional, live note or the reader (`John 3:16`, `1 Cor 13:4-7`) opens a verse popover (KJV or WEB), can be shared as an image, and plans track progress on the device (and across devices when signed in).
- **Live service**: *Admin > Live service > Go live* shows a pill on every page and opens `live.html` with the video and real-time notes. Each viewer reads up to 200 notes: stay inside the free Firestore reads (50,000 a day) by ending the service and clearing notes afterwards.
- **Prayer wall**: pastoral staff publish an edited, anonymous version of a request from *Admin > Prayer requests* (button with the praying-hands icon). Visitors tap *I prayed* (counted by the Worker, once per request per device).
- **Themes and motion**: a nav button cycles dark, light and high contrast (high contrast is also chosen automatically if the device asks for more contrast). Page changes use the View Transitions API where supported and are switched off for people who prefer reduced motion.
- **Listen mode**: a headphones button on each devotional reads it aloud with the browser's built-in voice (works offline; voices depend on the device).
- **Security**: strict Content-Security-Policy (no inline scripts), role-based Firestore rules, CodeQL, secret scanning, `security.txt` (renew `Expires` yearly: a test warns you 14 days before it lapses), see `SECURITY.md`.

## Development
```
npm install --legacy-peer-deps
python3 build-pages.py && python3 build-seo.py https://your-site && python3 build-icons.py   # or: npm run build
npm run test:unit            # Worker, media, member sync, push, scripture, CSP runner, budgets, security, backups
python3 test-e2e.py          # full browser suite (Playwright + Chromium), all network mocked
python3 test-a11y.py         # axe-core accessibility audit, desktop + mobile
node build-dist.mjs && python3 test-dist.py   # production build + smoke test
npm run test:rules           # Firestore rules (needs Java for the emulator); also test:rules:legacy
```
Run `python3 build-pages.py` after editing page templates in it, then `build-seo.py`; the generator is idempotent.

## Accessibility
Automated checks (axe, WCAG 2.2 AA rules) run in CI and currently report no serious or critical issues. Automation finds only part of the problems: before submitting to awards, test with VoiceOver (iOS/macOS), TalkBack (Android) and NVDA (Windows), keyboard only, 200% zoom, and add captions to every video.

## Known limits
- **GitHub Pages cannot send HTTP headers.** The production build adds the CSP as a `<meta>` tag (which cannot set `frame-ancestors`). For full header protection host on Cloudflare Pages (`_headers` is included) or Firebase Hosting (`firebase.json`).
- **Google Translate widget** is a third-party script under the strict CSP. Check it after deploying; if it fails, add `'unsafe-inline'` back to `script-src` in `csp.json`, `_headers` and `firebase.json` (they must match).
- **Rate limiting** in the Worker is per Cloudflare data centre and best-effort; Turnstile is the main defence.
- **Google Drive** is not a CDN: very large or very popular files can hit Google's download quotas. Use YouTube for video and archive.org for heavy audio if that happens. Drive uploads are capped at 200 MB in the admin.
- **Free tiers**: Firestore 50k reads / 20k writes a day; Workers 100k requests a day; GitHub Actions minutes are unlimited on public repos. Cloudflare/Firebase may change limits.
- **KJV** is public domain except under the UK Crown patent (printing in the United Kingdom). **WEB** uses "Yahweh" for the divine name.
- **Not included (needs your content or other people):** real photography and short video, copywriting in your church's voice, and reviewed translations into Yorùbá, Hausa, Igbo and French (the page-translate widget is machine translation: do not rely on it for theology). Flutterwave is not wired (Paystack only). Podcast audio on archive.org is supported by pasting links; there is no archive.org upload tool.
- **Tested with mocks only:** Paystack, Cloudflare, Firebase email links, push services and the camera scanner were exercised against simulated services. Do a real test payment (Paystack test key), a real RSVP and a real scan before announcing them.
- **Camera scanning** needs HTTPS and a browser with camera access; Chrome on Android uses the built-in detector, other browsers use the bundled jsQR decoder. Permissions-Policy allows the camera for this site only (`camera=(self)`).
- `firebase.js` still loads the Firebase SDK from Google's CDN; the Firestore emulator-based tests only run in CI or on a machine with Java.
